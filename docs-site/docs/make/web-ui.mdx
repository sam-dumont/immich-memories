# Use the web UI

The browser gives you a contact sheet to review and edit before rendering. Every cut and render uses the same engine as the CLI; **Copy as CLI command** gives you the command behind the job.

<ThemedScreenshot name="memory-brief" alt="The memory brief with type, dates and Cut button" />

## Where things are

| Page | Use it to |
|---|---|
| **Memory** | Choose a film and start its cut. |
| **Runs** | Review cuts, save revisions and render films, including automatic runs and failures. |
| **Suggestions** | See the memories automation would make next, and why. |
| **Settings** | Change configuration and confirm your people. |

On a phone, the navigation is at the bottom. Theme and interface language are remembered in that browser. The interface language does not change the film's language: [titles and languages](../reference/output-rendering.md#languages).

## Make and adjust a film

[Your first film](../get-started/first-film.mdx) walks through the whole process with a month. [Choose a film](./memory-types.mdx) covers trips, people, albums and other types.

The cut runs on the server, so you can close the tab and return later. The app follows the running job again. **Cancel** stops it; only one job runs at a time.

When the cut is ready, the app opens its run page under **Runs**. Open a shot to read its explanation or edit it. Use **Pool** to see pictures that did not make it. [Review and adjust](../how-it-chooses/overrule-it.md) explains revisions, missing shots and persistent exclusions.

## Find a finished film

**Runs** lists cuts and renders newest first. Open a run to review the cut, render another version or play its film.

Local films play on the page. Once an upload to Immich is confirmed, the local copy is removed and the run shows **Delivered to Immich** with a link.

Every run has **Copy report** and **Download report**, including failed runs. Review the redacted report before sharing it in an issue: [report](./cli/report.md).

## Change settings

Each setting shows where its value came from. A value set by the environment or `config.yaml` is locked here; change it at that source. Other values can be saved from the page.

API keys stay masked. To save secrets from the UI, configure `IMMICH_MEMORIES_SECRET_KEY`; keys already supplied through `.env` or `config.yaml` do not need this for normal use. [Configuration and the secret key](../run/environment-variables.md#the-secret-key).

Start with [People and home](../get-started/who-is-who.md), then [titles, maps and music](./titles-maps-music.md). Precedence, encryption, caches and job details: [Web UI reference](../reference/web-ui-details.md).

Open a run under **Runs** to render its original cut or any saved revision. **Title style** chooses a named preset, **Auto** or **Random** for this render. The **Render** panel also lets you choose a white or black **Opening and closing fade** for this film. **As configured** uses the saved `title_screens.fade_color` setting. [Titles, maps and music](./titles-maps-music.md) covers the lasting default.

### Input and saved edits

Concurrent saves keep separate numbered cut revisions. Invalid JSON text, NUL characters,
unpaired Unicode surrogates and nesting beyond 64 levels return a client error before a job
starts. Music uploads must contain an audio stream with a positive duration; truncated files
are refused, and an unavailable audio probe asks you to install FFmpeg.

If the cache or output disk fills up, the API returns a storage-full message (HTTP 507).
Free space before retrying. A failed revision save keeps earlier revisions and removes its
temporary file. A job whose initial record cannot be saved is stopped before returning the
error, so it cannot keep working without a job the page can follow or cancel.
