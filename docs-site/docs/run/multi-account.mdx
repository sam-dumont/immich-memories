# A second Immich account

Two phones, two Immich accounts, one family film. By default, the app reads only your primary
account. Connect a second account and explicitly select both when making a people film.
The primary remains the only upload destination.

## What you need

- A read-only API key created while signed in as the partner.
- Faces named in both libraries; each account has its own people IDs.
- Your primary account already connected and [family set up](../get-started/who-is-who.md).

Extra accounts are configured in YAML or environment variables. Settings shows the primary
connection only. The second account can be on another Immich server.

## The steps

Connect the account, bind matching people once, then make a film with both accounts selected.
The setup does not reset or re-tag faces in Immich.

## Connect the account

Add the partner alongside your primary connection:

```yaml
immich:
  url: "https://photos.example.com"
  api_key: "${IMMICH_API_KEY}"
  accounts:
    partner:
      url: "https://photos.example.com"
      api_key: "${PARTNER_IMMICH_API_KEY}"
```

For Docker, put the partner's key in `.env` and add this to the service's `environment:` block:

```yaml
      IMMICH_MEMORIES_IMMICH__ACCOUNTS__PARTNER__URL: "${IMMICH_URL}"
      IMMICH_MEMORIES_IMMICH__ACCOUNTS__PARTNER__API_KEY: "${PARTNER_IMMICH_API_KEY}"
```

Recreate with `docker compose up -d`. A line in `.env` alone does not reach the container.
Test the connection:

```bash
immich-memories config test
```

In Docker, prefix commands with `docker compose exec immich-memories`.
The output identifies the owner of each key:

```text
✓ Connected as Alex: Server: https://photos.example.com; API: v3
✓ Immich account partner: Connected as Sam: API: v3
```

The partner line must name the partner. If it names you, recreate the key while signed in as them.
Configuring the account alone does not change a film's source scope.

## Bind the same person across accounts

Sign in to Immich as the partner, open the person and copy their ID from `/people/<id>` in the URL.
Then bind it to the same person in this app:

```bash
immich-memories people bind "Alex" --account partner --id <person-id-in-partner-account>
```

Or use **Settings > People > Accounts**, choose the account, paste the ID and **Bind**.
The Accounts section appears once a second account is configured.

<ThemedScreenshot name="people-accounts-bind" alt="Person settings with a partner-account ID binding" />

Names are not used to guess identity. A binding preserves the person's confirmed details.
An ID already bound to somebody else is refused.

## Read both accounts into one film

```bash
immich-memories generate \
  --accounts primary,partner \
  --person "Alex" --memory-type person_spotlight --year 2026
```

In the web **New memory** page, select both under **Immich accounts to read**.

<ThemedScreenshot name="memory-brief-accounts" alt="New memory brief with both household accounts selected" />

The scope is exact: `primary,partner` reads both; `partner` alone excludes your primary.
Omitting accounts reads primary only. Identical files count once, downloads use the owning
account, and either owner's favourite counts. If one selected account cannot be read, the run
stops instead of silently dropping half the family.

Albums and trips still use primary only: `--accounts` is refused for those recipes.
[Duplicates and sharing](../how-it-chooses/family-audience-duplicates.md) covers the selection rules.

## What automation does across accounts

Set the same account scope for daily discovery:

```yaml
advanced:
  automation:
    accounts: [primary, partner]
```

Docker equivalent, in `environment:`:

```yaml
      IMMICH_MEMORIES_AUTOMATION__ACCOUNTS: '["primary", "partner"]'
```

Check the next proposal without making it:

```bash
immich-memories auto suggest
```

Trips stay primary-only. Saved-group films can use both accounts.
[Automation](../make/automate.md) explains priorities and cooldowns.

## Saved groups

Save a repeated people condition, such as either child:

```bash
immich-memories people group add "Kids" '"<alex-id>" OR "<sam-jr-id>"'
immich-memories generate --group "Kids" --accounts primary,partner --memory-type multi_person --year 2026
```

Use store person IDs from `people show`, so renaming does not break the group. `OR` means either
person; `AND` means both. The UI has **Saved groups** in People settings and group chips in the
memory brief. [CLI people tools](../make/cli/prepare.md) gives the complete group syntax.

### Someone only the partner account knows

The scan reads primary only, so a partner-only person needs an explicit entry:

```bash
immich-memories people export --to people.yaml
```

Keep every existing entry and add the person:

```yaml
people:
  # Keep the exported people above this entry.
  - name: Jo
    ids:
      partner: [<person-id-in-partner-account>]
```

```bash
immich-memories people import --from people.yaml --replace
```

`--replace` replaces the registry from that file; do not discard the exported entries.
A later primary scan preserves partner-only entries.

## Privacy notes

The partner key only goes to its configured server. The app reads the selected accounts' owned
pictures; partner sharing does not pull in a third person's library. Keys are redacted from logs
and diagnostic reports. Uploads always go to the primary account.
[Account-name rules and fields](../reference/config-reference.md#extra-accounts) are in the reference.
